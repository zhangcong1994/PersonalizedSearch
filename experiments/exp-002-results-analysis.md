# exp-002 实验结果汇总与分析

> 实验目标：在不引入微调的前提下，通过 Prompt 工程、多查询融合、HyDE 预回答扩展、PRF 伪相关反馈提升检索召回率
>
> 检索后端：BM25（jieba 分词, BM25Okapi）+ Dense（moka-ai/m3e-base, 768-dim）
>
> 评估数据：T2Ranking dev，采样 2000 条（实际有 qrels 的 1824 条），全量 230 万 passage 池
>
> 核心指标：Recall@50（召回阶段真实能力度量，给 Reranker 提供充足候选池）

---

## 二、分模块分析

### 2.1 E2a：单查询 Prompt 工程消融（7 组）

**实验变量**：仅改写 prompt 设计不同，其他条件完全相同（BM25/Dense 检索，top-50，单条查询）。

#### 各方案相对基线的 R@50 变化

| 对比维度 | 实验 | BM25 Δ R@50 | Dense Δ R@50 | 方向 |
|----------|------|-------------|--------------|------|
| 基线 | E2a-B0 | 0.1749 | 0.6277 | — |
| 通用 few-shot | E2a-B1 | +1.0% | +3.2% | ✅ |
| 规则增强 | E2a-P1 | +2.8% | +2.9% | ✅ |
| **领域 few-shot** | **E2a-P2** | **+5.0%** | **+4.0%** | ✅✅ |
| 对比 few-shot | E2a-P3 | -0.9% | +1.5% | ⚠️ |
| 类型感知 | E2a-P4 | -10.8% | -1.1% | ❌ |
| 关键词串 | E2a-P5 | -5.8% | -1.9% | ❌ |

#### 关键发现

1. **领域 few-shot（P2）在单查询改写中全面最优**
   - 在 BM25 和 Dense 上均以明显优势胜出
   - 比通用示例（B1）额外提升约 4% (BM25) / 0.8% (Dense)
   - 原因：LLM 见过来自 T2Ranking 同分布的真实查询示例后，改写风格更匹配该数据集的查询特征，产生的改写词更可能命中相关 passage

2. **对比示例（P3）反而退步**：展示「好改写 + 坏改写」对 LLM 形成了过度约束，导致 LLM 改写时过于保守，丢失了一些有用的扩展方向。这说明在 few-shot 场景下，"正面教学比反面教学更有效"

3. **类型感知改写（P4）在两个后端上都退化**：说明 query type 分类本身引入了额外的分类错误代价——一旦 query 类型被误判，整条改写方向就偏了。统一 prompt 的鲁棒性更好

4. **关键词串输出（P5）不如自然语句**：即使在 BM25 上，高密度关键词串也未能超越自然语句。原因是自然语句在 BM25 中被 jieba 分词后同样参与 term 匹配，且 IDF 会自动压低高频通用词（"的""了""是"等）。因此「自然语句 = 关键词串 + 结构化语义」，多出来的结构信息是有益的

### 2.2 E2b：Multi-Query RRF 融合消融（3 组）

**实验变量**：不同策略生成多条子查询 → 各自 BM25/Dense 检索 top-50 → RRF(k=60) 融合 → top-50。

#### R@50 对比（融合后 vs 最优子查询 vs 基线）

| 实验 | 后端 | 融合 R@50 | 最优子查询 R@50 | 基线 R@50 | 融合 vs 基线 | 融合 vs 最优子查询 |
|------|------|-----------|-----------------|-----------|-------------|-------------------|
| E2b-M1 | BM25 | 0.1738 | 0.1590 (sub_0) | 0.1749 | -0.6% | +9.3% |
| E2b-M1 | Dense | 0.6432 | 0.6212 (sub_1) | 0.6277 | +2.5% | +3.5% |
| E2b-M2 | BM25 | 0.1742 | 0.1645 (sub_0) | 0.1749 | -0.4% | +5.9% |
| E2b-M2 | Dense | 0.6227 | 0.6066 (sub_1) | 0.6277 | -0.8% | +2.7% |
| E2b-M3 | BM25 | 0.1826 | 0.1701 (sub_0) | 0.1749 | +4.4% | +7.3% |
| E2b-M3 | Dense | 0.6317 | 0.5943 (sub_0) | 0.6277 | +0.6% | +6.3% |

#### 关键发现

1. **RRF 融合始终优于任意单条子查询**（融合 vs 最优子查询 列全为正），说明多路之间的互补性确实存在——不同子查询覆盖了不同的相关 passage。但问题在于融合后的指标并不总是能超越基线。

2. **RRF 在 Dense 端未能超越最优单查询改写**：E2b-M1 (Dense R@50=0.6432) < E2a-P2 (Dense R@50=0.6531)。这说明在多路 Dense 检索场景下，RRF 在合并 ranking 时引入的排序噪声超过了多角度覆盖的互补增益——部分相关 passage 被从子查询中较高的排名拉低到了 50 位以下

3. **Step-back（M2）在 Dense 端导致退化**：抽象化改写（如「XX 是哪年成立的」→「XX 的历史背景和创立过程」）在 Dense 语义空间中可能锚定了错误的语义方向，召回了一大堆相关但不精确的 passage，挤占了原有相关 passage 的排序位置

4. **子查询数量与质量呈反比**：M3 有 4-7 条子查询，sub_3/sub_4 的 R@50 仅在 0.01-0.06 范围内（几乎可以忽略）。这说明 LLM 一次生成超过 3-4 条子查询后，后面的查询质量急剧下降

5. **M3 仅在 BM25 上有微弱优势**（0.1826 vs P2 的 0.1837），但 M3 需要一次生成 4-7 条子查询并做 4-7 次检索，而 P2 只需 1 条改写 + 1 次检索。考虑到 M3 增加了几倍的检索开销（且 API 调用可能更复杂），性价比远不如 P2

### 2.3 E2c：HyDE 预回答扩展消融（3 组）

**实验变量**：LLM 生成假答案文本（100-150 字）→ 用假答案文本做检索 → 与原始查询做 RRF 融合。

#### R@50 对比

| 实验 | 策略 | BM25 R@50 | Dense R@50 | BM25 Δ | Dense Δ |
|------|------|-----------|------------|--------|---------|
| E2c-H1 | HyDE only（只用假答案检索） | 0.1486 | 0.6172 | -15.0% | -1.7% |
| **E2c-H2** | HyDE + 原查询 RRF | **0.1944** | **0.6819** | **+11.1%** | **+8.6%** |
| E2c-H3 | HyDE 长度消融 RRF (不同生成字数) | 0.1925 | 0.6792 | +10.1% | +8.2% |

#### 关键发现

1. **HyDE + RRF 是最大赢家，在两个后端上都取得了全部 16 组实验的最高 R@50**
   - BM25: 0.1749 → 0.1944 (+11.1%)
   - Dense: 0.6277 → 0.6819 (+8.6%)
   - 这是唯一一个在两个后端上均显著超越基线和所有 Prompt 改写方案的策略

2. **纯 HyDE（不用 RRF）表现不佳**：只用假答案文本检索，BM25 和 Dense 上都不如直接用原查询。假答案虽然术语密度更高，但会引入幻觉——LLM 生成的答案中存在不准确或虚构的信息，这些信息偏离了真实 passage 的内容分布

3. **HyDE 为什么适合 RRF 融合**：原查询保留了精确的匹配信号（特别是实体名、专有名词等不可替换的词），而 HyDE 假答案提供了丰富但可能略微偏移的扩展信号。两者互补，RRF 取交集时优势最大化——原查询确保不偏，HyDE 确保不窄

4. **H2 和 H3 几乎无差距**：不同生成字数（50/100/200 字）对最终融合效果影响不大，说明 100-150 字的基本配置已经足够，不需要在长度上做细粒度优化

5. **HyDE 在 BM25 上的相对增益最大**（+11.1% vs Dense 的 +8.6%）：因为 BM25 完全依赖 term 匹配，短查询（5-15 字）的 term 覆盖率极低，而 100 字的假答案直接提供了 10-20x 的额外 term，命中概率大幅提升

### 2.4 E2d：PRF 伪相关反馈消融（2 组有效实验）

**实验变量**：第一轮检索 top-k → 从 top-k 中提取 TF-IDF 最高的 N 个 term → 拼接到原查询 → 第二轮检索。

#### R@50 对比

| 实验 | 策略 | BM25 R@50 | Dense R@50 | BM25 Δ | Dense Δ |
|------|------|-----------|------------|--------|---------|
| E2d-P1 | PRF (5 terms) | 0.1613 | 0.5672 | -7.8% | -9.6% |
| E2d-P2 | PRF (10 terms) | 0.1230 | 0.5564 | -29.7% | -11.4% |

#### 关键发现

1. **PRF 在低召回环境下是毒药**：在 BM25 场景下，第一轮 R@50 仅 17.5%，意味着 top-50 结果中 82.5% 都是不相关的 passage。从中提取 TF-IDF term 本质上是在提取噪声。扩展 term 越多（10 vs 5），退化越严重

2. **PRF 即使在 Dense 端也同样退化**：虽然 Dense 第一轮 R@50 有 62.8%，但仍有约 37% 的结果不相关。这些噪声 term 足以让向量的语义方向发生不可控的偏离

3. **PRF 更适合高召回场景**（如 R@50 > 90%），此时 top-50 中绝大多数是相关 passage，提取的 term 质量有保证。在当前数据集上，两个后端都远未达到这个前提条件

4. **应直接放弃 PRF 这条路**：在引入 Reranker 之前，单轮检索的召回上限不足以支撑 PRF 的正面效果

## 四、跨后端分析与总结

### 4.1 BM25 vs Dense 的绝对差距

```
BM25 最高 R@50: 0.1944 (E2c-H2)
Dense 最高 R@50: 0.6819 (E2c-H2)
差距: 3.5x
```

BM25 即使最优方案也只能召回不到 20% 的相关 passage，核心原因是：
- 短查询（5-15 字）与长 passage（中位 368 字）之间的 **词汇鸿沟**不可跨越
- 中文自然语言的同义词、近义词、上下位词极为丰富，纯 term 匹配天然遗漏大量相关文档
- jieba 分词在专业术语、新词上的分词错误进一步降低了匹配概率

### 4.2 一致有效的技术

| 技术 | BM25 有效? | Dense 有效? | 解释 |
|------|-----------|-------------|------|
| 领域 few-shot Prompt | ✅ +5.0% | ✅ +4.0% | 让 LLM 输出更匹配数据分布的改写词 |
| HyDE + RRF | ✅ +11.1% | ✅ +8.6% | 原查询精准 + 假答案丰富，完美互补 |
| 规则增强 Prompt | ✅ +2.8% | ✅ +2.9% | 更细的规则有小幅收益 |
| LLM 改写本身 | ✅ +1.0% | ✅ +3.2% | 改写增加 term/语义覆盖，始终正向 |

### 4.3 一致无效/有害的技术

| 技术 | BM25? | Dense? | 解释 |
|------|-------|--------|------|
| PRF 伪相关反馈 | ❌ -7.8% ~ -29.7% | ❌ -9.6% ~ -11.4% | 低召回场景下伪相关反馈 = 噪声注入 |
| 类型感知改写 | ❌ -10.8% | ❌ -1.1% | 类型分类错误 > 差异化收益 |
| Step-back 抽象化 | ❌ -0.4% | ❌ -0.8% | 语义偏移，召回大量不精确的相关文档 |

### 4.4 后端差异化的发现

| 技术 | BM25 表现 | Dense 表现 | 差异原因 |
|------|-----------|------------|----------|
| 关键词串（P5） | -5.8% | -1.9% | Dense 对语义更敏感，关键词串的语义贫瘠在 Dense 上惩罚较小 |
| 对比 few-shot（P3） | -0.9% | +1.5% | Dense 语义空间对改写方向的微小偏差容忍度更高 |
| Multi-Query RRF（M1） | -0.6% | +2.5% | Dense 的互补性更强，RRF 在 Dense 上的噪声影响小于 BM25 |

## 五、有前景的召回方案建议

基于 16 组实验的证据，以下是按优先级排序的下一步方向：

### 🥇 方向 1：HyDE × 领域 Few-Shot 组合（预期 Dense R@50 → 0.70+）

当前 E2c-H2 最大的问题是：HyDE 使用的 prompt 是基础 prompt，还未与 E2a-P2 的领域 few-shot prompt 结合。

**方案**：用 T2Ranking 的真实查询产出高质量领域 few-shot 示例，嵌入 HyDE prompt 中，让 LLM 在生成假答案时「模仿」领域内的写作风格和术语使用习惯。

**预期**：领域 few-shot + HyDE 独立各自提升约 4%，组合后预期在 Dense 端可突破 0.70。

### 🥈 方向 2：HyDE + 改写后查询 RRF（预期 Dense R@50 → 0.69+）

当前 E2c-H2 是 HyDE + 原查询（B0）做 RRF。但 E2a-P2 的改写查询（Dense R@50=0.6531）本身已大幅优于原查询（0.6277）。

**方案**：将 E2c-H2 的「原查询」替换为「P2 改写后的查询」→ HyDE + 最优改写 RRF。

**预期**：P2 改写查询比原查询多了约 2.5% 的 R@50，替代后预期融合结果能到 0.69+。

### 🥉 方向 3：2-3 条高质量子查询 RRF（精简后的 Multi-Query）

E2b 实验表明：子查询数量超过 3 条后质量急剧下降，但前 2-3 条子查询有明确的互补性。

**方案**：限制 LLM 只生成 2 条高质量子查询（如 HyDE 假答案 + P2 改写查询），而非 4-7 条。每路保证独立 R@50 > 0.55（Dense），再 RRF 融合。

**预期**：简化为 2-3 路后，RRF 噪声降低，可能超越当前最优的 E2c-H2。

### 🔮 方向 4：Dense + BM25 跨后端 RRF（长期方向）

当前所有实验都是 BM25 内融合或 Dense 内融合，尚未尝试跨后端融合。

**方案**：将 BM25 最优方案（HyDE RRF, 0.1944）与 Dense 最优方案（HyDE RRF, 0.6819）再做一次 RRF。

**预期**：BM25 和 Dense 召回的 passage 集合重叠度可能较低（BM25 依赖精确 term 匹配，Dense 依赖语义相似度），跨后端融合可能带来额外的互补增益。但 BM25 的绝对水平太低（<20%），边际贡献有限

## 六、实验范式说明

### 6.1 RAG 召回系统的标准架构

```
用户查询
   │
   ├─→ 路1: 稀疏检索 (BM25/TF-IDF)              → top-20
   ├─→ 路2: Dense 向量检索 (原查询)               → top-50
   ├─→ 路3: Dense 向量检索 (LLM 改写后查询)        → top-30
   ├─→ 路4: HyDE (假答案检索)                     → top-30
   └─→ 路5: 关键词匹配 (实体/专有名词定向)         → top-20
                │
                ▼
          RRF 融合 → 去重 → top-50 (粗排阶段)
                │
                ▼
          Reranker 精排 → top-10 (精排阶段)
```

### 6.2 本实验的位置

本实验（exp-002）聚焦的是 **粗排阶段** 的所有优化手段——这是整个 RAG 管道中召回能力的关键瓶颈。16 组实验覆盖了粗排阶段的四大类技术路线：

| 技术路线 | 实验 | 覆盖内容 |
|----------|------|----------|
| Prompt 工程 | E2a B1/P1/P2/P3/P4/P5 | 改写质量提升 |
| Multi-Query 融合 | E2b M1/M2/M3 | 多路召回 + RRF |
| HyDE 预回答 | E2c H1/H2/H3 | 假答案扩展检索 |
| PRF 伪相关反馈 | E2d P1/P2 | 从检索结果反馈扩展 |

### 6.3 与后续阶段的衔接

- **V0（当前）**：验证不改模型的情况下，Prompt/融合/扩展的上限
- **V1（后续）**：引入 Reranker 精排 → Recall@50 的增益才能转化为 MRR/NDCG@10 的最终用户体验提升
- **V2（远期）**：微调 Embedding 模型或多阶段检索器联合训练
