# exp-003 实验结果与分析

> 实验目标：通过多路召回 + RRF 融合，在不增加 LLM API 调用成本（≤2 次调用）的前提下，找到一个成本可控、Recall@50 最高的粗排方案
>
> 实验类型：纯后处理——从 exp-002 已保存的各路检索排名中读取 pid/rank，做 RRF 融合，无重新检索或 LLM 调用
>
> 核心指标：Recall@50（主指标）、MRR（辅助）

## 二、阶段一：路由组合 + Per-Route K 消融（验证集）

固定 RRF k=60，6 组方案 × 3 档 per-route K = 18 个实验点。

### 每路独立的 Recall@50（K=50 时）

| 路由 | R@50（验证集） | 说明 |
|------|---------------|------|
| D-P2 | 0.6611 | 最强单路 |
| D-B0 | 0.6465 | 原查询基线 |
| D-HyDE | 0.6283 | 假答案扩展 |
| B-P2 | 0.1892 | BM25 改写 |
| B-B0 | 0.1801 | BM25 原查询 |

### 阶段一关键发现

1. **Per-route K=50 在 K=20/30/50 中全面最优** — 对 S3 和 S4，K=50 比 K=20 分别高 3.8% 和 3.6%。说明在这个数据集上，"少取降噪"不成立，每路召回的有用信号分布在 50 条之内是均匀的。

2. **S4（Dense 三路 + BM25）第一** — R@50=0.7086，首次在 RRF 框架下突破 0.70。相比 S0 基线提升 9.6%，相比 exp-002 最优（E2c-H2, 0.6819 全量）的对应验证集参考值也有提升。

3. **S5（加 BM25 改写）反而退步** — 五路不如四路（0.6729 → 0.6931 vs S4 的 0.6853 → 0.7086），多一路低质量的 BM25-P2 稀释了 RRF 排名信号。

4. **S3 vs S1** — 三路比二路额外提升 2.0%（0.7044 vs 0.6838），但需要多 1 次 API 调用（2 vs 1）。成本-收益需要权衡。

## 三、阶段二：RRF k 消融（验证集）

对阶段一 Recall@50 top-3 的配置（`S4_K50`、`S3_K50`、`S3_K30`），消融 RRF k ∈ {30, 60, 90}。

### Recall@50

| Config | RRF k=30 | RRF k=60 | RRF k=90 |
|--------|----------|----------|----------|
| **S4_K50** 🥇 | 0.7081 | 0.7086 | 0.7086 |
| S3_K50 | 0.7044 | 0.7044 | 0.7044 |
| S3_K30 | 0.6953 | 0.6953 | 0.6953 |

### MRR

| Config | RRF k=30 | RRF k=60 | RRF k=90 |
|--------|----------|----------|----------|
| **S4_K50** | **0.5379** | 0.5260 | 0.5241 |
| S3_K50 | 0.5246 | 0.5232 | 0.5221 |
| S3_K30 | 0.5270 | 0.5261 | 0.5235 |

### 阶段二关键发现

**RRF k 对所有指标的区分度极低** — R@50 完全一致（0.7081 → 0.7086，差异 < 0.001），仅 MRR 有微弱差异（k=30 的 MRR 比 k=60 高 +0.012）。核心原因是各路由的排名分布均匀、互补性强，使得 RRF 对 k 不敏感。

**最优配置：S4_K50_RRFk=60**（Recall@50 最高 0.7086，MRR=0.5260）。

## 五、综合分析与结论

### 5.1 S4 是最优方案

```
S4 = D-B0 + D-P2 + D-HyDE + B-B0
     原查询   改写    假答案   BM25原查
     Dense   Dense   Dense   BM25
     (0 API) (1 API) (1 API) (0 API)
                     总计：2 次 LLM API 调用
```

- **测试集 Recall@50 = 0.6912**，相比基线 S1 提升 13.5%
- **Hit@50 = 0.8991**，90% 的查询在 top-50 中至少有 1 条相关 passage
- **每路 K=50、RRF k=60** 为最优配置

### 5.2 核心消融结论

| 消融维度 | 发现 | 推荐 |
|----------|------|------|
| **路数** | 4 路 > 3 路 > 2 路，但 5 路退步（BM25-P2 引入噪声） | ≤4 路为甜蜜点 |
| **Per-route K** | K=50 全面碾压 K=30/20。有用信号在 50 条内分布均匀 | 固定 K=50 |
| **RRF k** | k=30/60/90 的 R@50 几乎无差异。仅 MRR 在 k=30 时略高 | 固定 k=60（文献标准） |
| **BM25 价值** | B-B0 贡献 +0.42%（验证集 R@50），边际但非零 | 保留 |
| **跨后端融合** | S4 > S3，跨后端互补增益得到证实 | 值得进一步探索 |

### 5.3 与 exp-002 对比

| 来源 | 配置 | R@50 | 说明 |
|------|------|------|------|
| exp-002 最优 | E2c-H2 (HyDE+原查询 2路) | **0.6819** | 全量 1824 条 |
| exp-002 基线 | E2a-B0 (原查询) | 0.6277 | 全量 1824 条 |
| **exp-003 测试集** | **S4 (Dense三路+BM25)** | **0.6912** | **测试集 912 条** |
| exp-003 验证集 | S4 (Dense三路+BM25) | 0.7086 | 验证集 912 条 |

> ⚠️ 由于 exp-003 是 50/50 分割，912 条子集上的 R@50 绝对值可能与 exp-002 的 1824 条全量略有差异。但相对提升趋势一致。

### 5.4 推荐方案

```
🏆 推荐方案：S4（D-B0 + D-P2 + D-HyDE + B-B0）
   Per-route K: 50
   RRF k:      60
   成本:       2 次 LLM API 调用（改写 + HyDE）
   测试 R@50:  0.6912
   测试 MRR:   0.4965
```

**这条路已经满足了"成本可控 + 高 R@50 + 3~5 路"的目标。**

## 六、后续方向

### 6.1 近期可做
- **差异化 per-route K**：高质量路（D-P2）取 50 条，低质量路（B-B0）只取 20 条，探索是否进一步降噪
- **BM25 路替换**：B-B0（R@50=0.17）换成质量更高的 BM25 路（如 BM25-HyDE），但需额外 API 调用
- **全量跑**：用 22,812 条全量数据跑最优方案，出最终论文指标

### 6.2 中期方向
- **Reranker 精排**：在 R@50=0.69 的候选池上训练/使用 Reranker → MRR@10 有望大幅提升
- **Query 级别分析**：分析哪些 query 从哪路获益最大，建立自适应路由选择策略
