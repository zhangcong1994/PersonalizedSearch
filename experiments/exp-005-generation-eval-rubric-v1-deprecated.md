# Exp-005：端到端生成质量评估 —— 维度与评分标准（v1 废案）

> 创建日期：2026-05-21
>
> 废弃日期：2026-05-23
>
> 废弃原因：该框架基于 RAG 评估范式（以文档一致性为核心），不适合 AI 搜索场景。缺少多源综合质量、引文与可信度、安全合规等关键评估维度。新版见 `exp-005-ai-search-eval-rubric.md`。
>
> 目标：定义 LLM-as-a-Judge 生成质量评估的四个维度及 4 档评分标准

---

## 一、评估框架概述

### 1.1 评估范式

采用 **LLM-as-a-Judge** 范式（参考 Zheng et al., 2023, *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*），由强 LLM（如 DeepSeek-chat 或 GPT-4o-mini）作为裁判，对 RAG 系统生成的答案进行多维度评分。

### 1.2 四维评估体系

| 维度 | 英文 | 评估输入 | 核心问题 |
|------|------|---------|---------|
| **忠实度** | Faithfulness | 答案 + 检索文档 | 答案是否忠实于提供的文档？有没有编造？ |
| **切题度** | Answer Relevance | 答案 + 用户查询 | 答案是否直接回应了用户的问题？ |
| **正确度** | Correctness | 答案 + 用户查询 + 检索文档 | 答案中的事实和推理是否正确？ |
| **完整度** | Completeness | 答案 + 用户查询 + 检索文档 | 答案是否覆盖了查询所需的全部关键信息？ |

### 1.3 档位设计

采用 **4 档 forced-choice 评分**（1-4），去除中立项，强制 judge 在"不可用 / 有缺陷 / 基本合格 / 优秀"之间做出选择。

**设计依据**：
- Dell 企业级 RAG 评估（Chhabra et al., 2026, *Case-Aware LLM-as-a-Judge Evaluation for Enterprise-Scale RAG Systems*）采用 4 级严重度分级（Critical / Moderate / Minor / No Meaningful Issues），证明 4 档比 5 档 Likert 减少了中立项带来的评分模糊
- Forced-choice Likert scale 在心理测量学中广泛使用，去掉中立项可提升区分度

### 1.4 四个维度之间的关系

```
忠实度 ≠ 正确度
├── 忠实度高 + 正确度高 → 理想情况（文档正确，答案忠实复述）
├── 忠实度高 + 正确度低 → 文档本身有误，答案忠实复述了错误
├── 忠实度低 + 正确度高 → 答案正确但引用了文档外的知识（编造但对）
└── 忠实度低 + 正确度低 → 严重幻觉

在本项目场景中：
  - T2Ranking passage 来自可信来源，假设文档内容为 truthful
  - Judge prompt 明确要求以文档为事实依据
  - 因此正确度 ≈ 忠实度 + 逻辑推理正确性
  - 两者区分点：正确度额外惩罚"忠实但推理错误"的情况
    （如文档说 A>B 和 B>C，答案错误推理出 C>A）
```

## 二、维度一：忠实度（Faithfulness）

> **核心问题**：答案中的事实陈述是否都能被提供的文档所支持？答案是否编造了文档中不存在的信息？
>
> **评估输入**：答案 + 检索文档

| 档位 | 标签 | 定义 |
|------|------|------|
| **1** | 严重编造 | 答案中**多数关键信息无法在文档中找到依据**，或包含**明显与文档矛盾**的事实。用户如果相信此答案，会被严重误导。例：文档说"A 公司成立于 2010 年"，答案说"A 公司成立于 2005 年"。 |
| **2** | 部分偏差 | 答案中**有一两处关键信息无法被文档支持**（如编造了一个文档未提及的数字/人名/时间），或对文档信息做了**错误引申**。其他大部分内容有据可依。例：文档说"该药物有效"，答案引申为"该药物对所有人群都有效"（文档未提及人群）。 |
| **3** | 基本忠实 | 答案中的**所有核心事实均可在文档中找到出处**。可能存在极个别不重要的细节略微偏离文档（如措辞不够精确，但不影响事实准确性）。例：文档说"提升约 20%"，答案说"提升 20%"（去掉了"约"字，但数字一致）。 |
| **4** | 完全忠实 | 答案中的**每一句事实陈述都能在文档中找到直接或可直接推断的依据**。未引入任何文档未包含的信息。引用准确无误。 |

**关键区分边界**：
- 1 vs 2：**错误量级**——"多数关键信息编造" vs "少量偏差"
- 3 vs 4：**有无任何不忠实**——4 分要求零编造，3 分允许极轻微的不精确

## 三、维度二：切题度（Answer Relevance）

> **核心问题**：答案是否直接回应了用户的查询？是否答非所问、绕圈子、或说了大量无关内容？
>
> **评估输入**：答案 + 用户查询

| 档位 | 标签 | 定义 |
|------|------|------|
| **1** | 答非所问 | 答案的内容与用户查询**几乎无关**，或**完全回避**了用户真正想问的问题。用户看完这个答案后，仍然不知道问题的答案。例：用户问"A 和 B 的区别"，答案只泛泛介绍了机器学习的定义。 |
| **2** | 部分相关 | 答案涉及了查询的主题方向，但**未直接回答核心问题**。例：用户问"A 和 B 的区别"，答案只详细介绍了 A 而未对比 B；或用户问"具体的数字"，答案只给了模糊的方向性描述。 |
| **3** | 基本切题 | 答案**直接回应了用户查询的核心问题**，但可能包含了少量无关信息（如不必要的背景介绍），或对多义词/模糊查询的理解略有偏差但方向正确。例：用户问"苹果的市值"，答案正确给出了市值但额外花了一段讲苹果的历史。 |
| **4** | 精准切题 | 答案**精准地、直接地回应了用户查询的每一个方面**。没有任何无关、绕圈子或答非所问的内容。如果用户有隐含意图（如多义词的不同含义），答案正确识别并回应了最合理的那个。 |

**关键区分边界**：核心是"用户看完答案后，是否得到了他问的东西"
- 2 vs 3：**是否回答了核心问题**——2 分是"沾边但没回答到"，3 分是"回答了但有废话"
- 3 vs 4：**是否干净利落**——4 分要求无任何无关内容，直击要害

## 四、维度三：正确度（Correctness）

> **核心问题**：答案中的事实信息是否符合客观真实（或符合检索文档所代表的"真实"）？推理过程是否正确？
>
> **评估输入**：答案 + 用户查询 + 检索文档
>
> **注意事项**：
> - 与本项目的 judge prompt 约定，**以提供的文档内容作为事实依据**
> - 如果文档中没有提及某信息，不应据此判定答案不正确（那是忠实度维度的问题）
> - 如果答案中的陈述与文档明显矛盾，则判定为不正确
> - 如果答案忠实复述了文档内容，但推理过程（如因果推断、数值计算、逻辑推导）有误，同样判定为不正确

| 档位 | 标签 | 定义 |
|------|------|------|
| **1** | 严重错误 | 答案中**多个核心事实与文档信息明显矛盾**，或给出了**完全错误的结论**。这些错误会导致用户产生严重误解。例：文档说"该政策 2023 年实施"，答案说"该政策 2020 年实施"；或文档说 A>B 且 B>C，答案却说 C>A。 |
| **2** | 部分错误 | 答案整体方向大致正确，但**包含一两个事实性错误**（如年份不对、数据偏差、归因错误），或**关键结论的推理过程有明显漏洞**。例：文档说"增长 15%"，答案说"增长 18%"；或正确列举了多个原因但错误地将主因归为次因。 |
| **3** | 基本正确 | 答案的**所有核心事实和结论均与文档信息一致**。可能存在个别非核心细节的不精确（如用词不够严谨、"大约"之类的修饰词缺失），但不影响整体正确性。例：文档说"试验持续约 6 个月"，答案说"试验持续 6 个月"。 |
| **4** | 完全正确 | 答案中的**所有事实信息、推理过程和结论都准确无误**。可以用作文档内容的权威引用。即使是挑剔的领域专家也挑不出事实性错误。 |

**关键区分边界**：
- 1 vs 2：**是否整体方向就错了**——1 分是根本性错误，2 分是局部偏差
- 3 vs 4：**是否有任何不精确之处**——4 分要求零错误，包括推理过程

## 五、维度四：完整度（Completeness）

> **核心问题**：答案是否覆盖了查询所需的全部关键信息？是否有重要遗漏？
>
> **评估输入**：答案 + 用户查询 + 检索文档

| 档位 | 标签 | 定义 |
|------|------|------|
| **1** | 严重缺失 | 答案**几乎没有提供任何实质性的信息**。只回答了一两个字，或仅给出了一个极其空泛的回应。用户需要追问才能获得任何基本答案。例：用户问"A 是什么原理"，答案回答"A 是一种常见现象"。 |
| **2** | 明显不完整 | 答案提供了一部分正确信息，但**遗漏了一个或多个查询明确要求的关键信息点**。例：用户问"A 的定义、原理和应用"，答案只介绍了定义和原理，完全未提应用；或对比类查询只详细介绍了其中一方，另一方一笔带过。 |
| **3** | 基本完整 | 答案**覆盖了查询的所有核心信息需求**。可能存在一些可选的补充信息未被提供（如额外的背景、相关案例、最新进展），但用户的核心疑问已得到满足。用户读完后不需要再追问基本问题。 |
| **4** | 详尽完整 | 答案**全面、细致地覆盖了查询的方方面面**。不仅回答了用户明确问到的内容，还补充了合理的背景信息、相关知识点或注意事项。用户读完不需要再追问任何问题。 |

**关键区分边界**：
- 1 vs 2：**有无实质内容**——1 分是几乎没有内容，2 分是有内容但不全
- 3 vs 4：**用户是否需要追问**——3 分满足直接需求，4 分预判并回答了潜在后续问题

## 六、评分输出格式

每个维度单独评分，Judge LLM 每次调用同时评估四个维度，输出结构化 JSON：

```json
{
  "faithfulness": {
    "score": 3,
    "reason": "答案的核心事实（药物名称、作用机制、临床试验结果）均可在文档中找到明确出处。仅'约有 20% 的患者'一处省略了文档中的'约'字，但不影响事实准确性。"
  },
  "relevance": {
    "score": 4,
    "reason": "答案直接回应了用户'该药物的作用机制是什么'的查询。内容全部围绕作用机制展开，无任何偏离主题的内容。"
  },
  "correctness": {
    "score": 3,
    "reason": "答案中的事实信息均与文档一致。但'约 20%'简化为'20%'属于轻微不精确，不影响整体正确性。"
  },
  "completeness": {
    "score": 2,
    "reason": "答案详细介绍了作用机制，但用户还询问了'副作用和注意事项'，这部分在答案中完全缺失。文档中实际上有这部分信息。"
  }
}
```

## 七、参考资料

### 核心参考

| 来源 | 标题 | 相关贡献 |
|------|------|---------|
| **RAGAS** (Es et al., 2023, EACL 2024) | *RAGAS: Automated Evaluation of Retrieval Augmented Generation* | 提出 Faithfulness、Answer Relevance 等无参考评估指标；LLM-as-a-Judge 范式用于 RAG 评估的开创性工作；rubric-based 评分机制 |
| **Azure AI Foundry** (Microsoft, 2024) | *Retrieval-Augmented Generation (RAG) evaluators* | 提出 Groundedness、Relevance、Completeness 三维评估体系；5 档内置评分标准；模型配置与最佳实践 |
| **CCRS** (Muhamed et al., 2025, SIGIR 2025 LLM4Eval Workshop) | *CCRS: A Zero-Shot LLM-as-a-Judge Framework for Comprehensive RAG Evaluation* | 提出 Contextual Coherence、Question Relevance、Information Density、Answer Correctness、Information Recall 五维度；0-100 连续评分；零样本端到端 judge 范式 |
| **Dell Enterprise** (Chhabra et al., 2026) | *Case-Aware LLM-as-a-Judge Evaluation for Enterprise-Scale RAG Systems* | 4 级严重度分级（Critical / Moderate / Minor / No Meaningful Issues）；严重度感知评分协议；企业级多轮 RAG 评估 |

### 方法论参考

| 来源 | 标题 | 相关贡献 |

| **PHAROS** (tewari et al., 2025) | *RAG Evaluation Guide* | Faithfulness 0-1 连续值 + 4 级阈值解读（Excellent >0.9, Good 0.7-0.9, Fair 0.5-0.7, Poor <0.5）；逐 claims 分解的 faithfulness 计算 |
