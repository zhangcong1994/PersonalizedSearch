## 一、核心建议：过滤 Judge ≠ 评估 Judge

exp-009 阶段四计划用 deepseek-chat 单维度准确性评分，阈值 `< 3` 则丢弃。这个方向正确，但需要区分两个场景：

| 场景 | 目标 | 维度选择 | 成本敏感度 |
|------|------|---------|:---------:|
| 模型评估（exp-005） | 区分模型好坏 | 全 6 维，全面画像 | 低（评估一次性） |
| 数据过滤（exp-009） | 确保教师答案本身可信 | 精简维度，高频调用 | 高（每条数据都评） |

**关键洞察**：数据过滤的 Judge 需要在成本和效果间取得平衡，但**不能牺牲关键维度的覆盖**。

## 二、建议改进：双维度过滤（准确性 + 引文质量）

### 2.1 为什么需要引文质量？

exp-009 的训练数据设计中，**引文强调类别占 12%**，目标是"最大短板的靶向修复"。但如果过滤阶段只评准确性，会出现：

```
场景: 教师答案事实全对，但完全没有引用
Judge 评分: 准确性 = 3（合格）
当前策略: 保留 → 进入标准池（55%）
问题: 教学生模型"答对了就行，不需要引用"
后果: 与引文强调类别的训练目标直接矛盾
```

### 2.2 建议的联合阈值策略

```python
def filter_with_dual_threshold(accuracy: int, citation_quality: int) -> str:
    """
    返回值: "retain_standard" | "retain_non_standard" | "discard"
    """
    if accuracy >= 4:
        if citation_quality >= 3:
            return "retain_standard"       # 完美数据
        elif citation_quality == 2:
            return "retain_non_standard"   # 引文粗糙，降级
        else:
            return "discard"               # 准确但无引文，丢弃
    elif accuracy == 3:
        if citation_quality >= 3:
            return "retain_standard"       # 准确性刚及格+引文可靠
        elif citation_quality == 2:
            return "retain_non_standard"   # 双刚及格，降级
        else:
            return "discard"               # 准确性刚及格但引文差
    else:
        return "discard"                   # accuracy <= 2，直接丢弃
```

### 2.3 成本估算

| 方案 | 维度 | API 调用量 | 成本（5000条） |
|------|------|:---------:|:-------------:|
| 当前设计 | 准确性 | 5000 次 | ~¥4 |
| 建议方案 | 准确性 + 引文质量 | 5000 次（同一次调用评两维） | ~¥6 |
| 全 6 维 | 同 exp-005 | 5000 × 2 批 | ~¥15 |

**结论**：双维度仅增加 ¥2，但显著提升过滤质量。强烈推荐。

## 三、Judge 的三大偏差及对策

### 3.1 Verbosity Bias（长度偏好）

**问题**：Judge 倾向于给长答案打高分。在数据过滤中，这会**系统性保留冗长答案、丢弃简洁但正确的答案**。

**检测方法**：
```python
from scipy.stats import spearmanr
rho, p_value = spearmanr(answer_lengths, judge_scores)
# 如果 |rho| > 0.3，存在显著长度偏好
```

**对策**：在 Judge prompt 中显式加入：

```
评分规则补充：
- 评分不考虑答案长度
- 简洁准确的答案和详细完整的答案可以得同样的分
- 冗余堆砌不加分，精炼表达不扣分
```

### 3.2 Leniency Bias（宽容偏好）

**问题**：Judge 倾向于给"还行但不优秀"的答案打 3 分，导致 2 分和 3 分的区分度很低。在 1-4 分体系中，**3 分是一个巨大的灰色地带**。

**对策**（按有效性排序）：

1. **锚定示例（最有效）**：在 prompt 中嵌入 2 分和 3 分的对比示例

```
准确性评分示例：

【2 分案例】
文档: "该公司2020年营收增长15%，达到120亿元"
答案: "该公司营收增长了18%"  # 数字偏差
评分: 2分 - 核心事实存在偏差（15%→18%）

【3 分案例】
文档: "该公司2020年营收增长约15%，达到120亿元"
答案: "该公司营收增长15%"  # 省略"约"但数字正确
评分: 3分 - 核心事实一致，轻微不精确
```

2. **强制理由先行**：要求 Judge 先写 reason，再给分

```
输出格式（严格遵循）：
1. 先列出答案中的关键事实主张（≥3条）
2. 逐条检查是否与文档一致
3. 最后给出评分

{"reasoning": "...", "accuracy": {"score": 3, "reason": "..."}}
```

3. **双阈值过滤**：不只看分数，还看 reason 中的关键词

```python
LENIENT_KEYWORDS = ["略有偏差", "部分不准确", "轻微错误", "存在偏差"]
if score == 3 and any(kw in reason for kw in LENIENT_KEYWORDS):
    # 即使打了3分，reason中透露了问题 → 降级审查
    return "retain_non_standard"
```

### 3.3 Position Bias（位置偏好）

**问题**：批量提交时，先出现的样本可能获得更仔细的评估。

**对策**：
- 每次只提交一条数据（exp-009 设计已满足）
- 如需批量提效，随机打乱提交顺序

## 四、Judge 捕捉不到的"隐性毒药"

### 4.1 表面一致但语义泛化

**场景**：
```
文档: "2020年一线城市用户增长15%"
答案: "用户增长率为15%"  # 看似一致，但不当泛化了"一线城市"
```

**Judge 行为**：看到数字匹配就给高分，不会检查语义范围。

**对策**：在准确性 prompt 中加入：

```
额外检查项：
- 答案中的限定词（如"约""部分""在X条件下"）是否与文档一致？
- 答案是否不当泛化了文档中的限定性陈述？
- 如发现不当泛化，准确性扣1分
```

### 4.2 虚假引用

**场景**：
```
答案: "该方法的有效率为85% [来源: 1]"
文档1: "该方法在临床试验中..."  # 实际不包含85%这个数字
```

**Judge 行为**：看到"有引用标记"就给引文质量 3 分，但实际是虚假引用。

**对策**：在引文质量 prompt 中嵌入抽查步骤：

```
评分步骤：
1. 找出答案中所有 [来源: N] 标记
2. 随机抽取 2 个，检查对应文档是否确实包含该陈述
3. 如发现虚假引用（文档不包含该内容），引文质量直接评 1 分
4. 如发现引用指向错误文档（内容在其他文档中），评 2 分
```

### 4.3 伪拒答

**场景**：桶 C 的数据中，教师说"根据现有资料无法确定"，但**实际上 top-10 中有相关文档只是教师没找到**。

**危害**：这种"伪拒答"进入 SFT 训练，会教模型"懒得找就拒答"。

**对策**：对桶 C 的拒答样本，额外用 Judge 做检索充分性判断：

```
Prompt:
给定以下检索文档和用户问题，判断：
1. 文档中是否包含能够回答该问题的信息？
2. 如果包含，教师说"无法确定"是否合理？

输出格式：
{"has_relevant_info": true/false, "refusal_valid": true/false, "reason": "..."}
```

过滤规则：`has_relevant_info=true AND refusal_valid=false` → 丢弃（伪拒答）

## 五、校准机制——黄金标准集

### 5.1 为什么需要校准？

LLM-as-a-Judge 的评分可能随时间漂移、随 prompt 变化而变化。没有校准，无法判断过滤结果是否可靠。

### 5.2 建议做法

1. **采样**：从教师生成结果中随机抽 100 条，确保 A/B/C 各桶都有代表
2. **人工标注**：标注准确性（1-4）和引文质量（1-4）
3. **Judge 评分**：用同一 prompt 对 100 条评分
4. **计算一致性**：

```python
from sklearn.metrics import cohen_kappa_score

# 精确一致率
exact_match = sum(judge[i] == human[i] for i in range(100)) / 100

# ±1 一致率
within_one = sum(abs(judge[i] - human[i]) <= 1 for i in range(100)) / 100

# Cohen's Kappa
kappa = cohen_kappa_score(human_scores, judge_scores)
```

**目标值**：
| 指标 | 目标 |
|------|:----:|
| 精确一致率 | > 70% |
| ±1 一致率 | > 90% |
| Cohen's Kappa | > 0.6 |

5. **迭代优化**：一致性不达标 → 调整 prompt 中的示例和措辞 → 重新校准

### 5.3 校准集的维护

- **版本控制**：每次调整 prompt 后，记录版本号和一致性结果
- **定期复测**：每周用校准集复测一次，监控 Judge 稳定性
- **漂移检测**：如果一致性下降 > 5%，触发 prompt 审查

## 六、Judge 模型选择建议

### 6.1 模型对比

| 模型 | 准确性评估 | 引文质量评估 | 成本 | 推荐场景 |
|------|:---------:|:----------:|:----:|---------|
| deepseek-chat | 好 | 一般 | 低 | 单维度快速过滤 |
| deepseek-reasoner | 很好 | 好 | 中 | **双维度过滤（推荐）** |
| gpt-4o-mini | 好 | 好 | 中 | 双维度备选 |
| glm-4-flash | 一般 | 一般 | 低 | 预过滤（粗筛） |

### 6.2 为什么推荐 deepseek-reasoner？

exp-005 的双 Judge 校准已证实：**thinking 模型在需要"仔细比对文档和答案"的任务上显著优于非 thinking 模型**。

数据过滤的核心任务正是"比对"：
- 答案中的事实 vs 文档中的陈述
- 引用标记 vs 实际文档内容

多花的 ¥2-3 换来更可靠的过滤，对于 SFT 训练数据的质量保障非常值得。

## 七、完整过滤流程建议

```
阶段四 Judge 过滤流程（改进版）：

1. 规则过滤（快速、零成本）
   ├── 空/超长/重复/非中文 → 丢弃
   ├── 意外拒答（桶 A/B 中出现拒答） → 丢弃
   └── 无引用标记（桶 A 标准数据） → 降级为非标准

2. Judge 双维度评分（deepseek-reasoner，~¥8）
   ├── 准确性 (1-4) + 引文质量 (1-4)
   ├── 联合阈值过滤（见 2.2）
   ├── 引文真实性抽查（嵌入 prompt）
   └── 语义泛化检查（嵌入 prompt）

3. 拒答样本专项检查（桶 C 专属，~¥1）
   ├── Judge 判断"文档是否确实不足以回答"
   ├── 伪拒答 → 丢弃
   └── 真拒答 → 保留

4. 校准验证（一次性，~¥1）
   ├── 随机抽 100 条人工标注
   ├── 计算 Judge-Human 一致性
   └── 一致性不达标 → 调整 prompt 重新过滤

总成本: ~¥10（比原设计增加 ¥6，但过滤质量显著提升）
```
