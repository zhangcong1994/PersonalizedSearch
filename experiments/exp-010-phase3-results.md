## Phase 3 Prompt 改动

在 V1-full 基础上，经过多轮迭代回退后，最终保留了 5 处差异：

### 1. 查询类型判断（~300 字新增）

```
=== 查询类型判断（先读这条再回答）===

先判断用户问题属于哪种类型，然后选择对应的回答结构：
- 问「是什么/多少/谁」→ 事实型 → 1-3 句话说清答案 + 引用，再按需补充细节
- 问「区别/对比/vs」→ 对比型 → 用表格并排展示差异 + 简短解读
- 问「怎么做/如何/步骤」→ 操作型 → 前置条件 + 分步编号列表 + 注意事项
- 问「为什么/原因」→ 原因型 → 核心原因概述 + 逐点展开
- 问「发展/现状/评价」→ 综述型 → 总览概述 + 分主题展开
```

靶向 Phase 1 未解决的用户体验问题（3.42），将 V1 模糊的"用什么格式由问题决定"替换为 5 个精确的 query→format 映射。

### 2. ABCD 资料策略（~200 字新增）

```
=== 面对不同资料情况的回答策略 ===

情况 A：资料完全不相关或为空
→ 说「根据现有资料无法确定」，可建议换个方式提问。不要编造。

情况 B：资料部分相关但不完整（只覆盖了问题的一部分）
→ 先回答资料中有答案的部分，然后诚实说明
→ 不要因为信息不完整就完全不回答，也不要编造缺失的部分。

情况 C：资料之间存在明显矛盾
→ 呈现双方说法，标注分歧
→ 不要按自己的想法选一边站队。

情况 D：资料充足且一致
→ 正常回答。按整合步骤融合多源信息。
```

靶向 Phase 1 的两难问题：CoT 推理中模型在信息半截时行为不稳定（有的完全拒答，有的编造缺失部分）。情况 B 提供了第三条路——先答有答案的部分再诚实标注。

### 3. 核心原则新增第 5 条

"语言简洁直接，篇幅精当" — 从 V1 的回答结构区块提升为核心原则。

### 4. 对比示例

示例 1（正面）和示例 3（正面）与 V1 相同。中间插入示例 2（❌ 逐篇罗列 → ✅ 合并整合）。

### 5. 区块顺序重排

V1：`核心原则 → 整合步骤 → 回答结构 → 避免行为 → 示例`
V3：`查询类型 → 资料策略 → 整合步骤 → 核心原则 → 避免行为 → 示例`

核心原则从 prompt 开头移到了整合步骤之后。

### 回退的改动

- 硬规则区（Phase 2 证明有害，已删除）
- 整合步骤精简（恢复 V1 完整版）
- 核心原则压缩（恢复 V1 完整版 + 第 5 条）
- 避免以下行为（恢复 V1 原文）

## 分析

### 发现 1：两个新增大块各有真实收益，但被系统性代价抵消

查询类型判断把 UX 推到 3.55（+0.13），ABCD 策略把相关性推到 3.66（+0.11）。这两项收益是独立的、可归因的——前者解决"格式是否对路"，后者解决"是否过度拒答"。

但收益被三个系统性代价抵消：

| 收益 | 代价 |
|------|------|
| UX +0.13 | 准确性 −0.12 |
| 相关性 +0.11 | 引文 −0.07 + 安全性 −0.07 |
| | F 级 +7（14 → 21） |

### 发现 2：准确性首次跌破 3.0

V1 的准确性已经从 V0 的 3.29 跌到 3.10（−0.19），V3 在此基础上继续跌到 2.98（−0.12）。累积从 V0 到 V3 跌了 0.31。F 级 21 条也是全系列最高。

根因：ABCD"情况 B"的部分回答策略在解决"过度拒答"的同时，让模型在更多边界 case 上选择了"先答再说"——但模型在信息不完整时的"部分回答"不够精确，导致编造残存。

### 发现 3：4 分整合创了新高

4 分整合从 V1 的 11 条涨到 18 条（+7）。ABCD 策略要求模型在情况 C（矛盾）中"呈现双方说法"而非"选边站队"，这实际上是对整合步骤的补充训练。但 3 分整合从 141 跌到 134——两极分化加剧。

### 发现 4：V1-full 是跨 Phase 最优 prompt

全部 4 个 Phase 拉通：

| Phase | 版本 | 总分 | 核心改动 | 判定 |
|---|:---:|:---:|------|:---:|
| — | V0 | 63.8 | 基线（`[文档 N]` 格式修正后） | — |
| 1 | V1-full | **64.2** | 分步整合指令 + 温和约束 | **最优** |
| 2 | V2 | 59.3 | V1 + 硬规则区 + 对比示例 | 崩溃 |
| 3 | V3 | 63.5 | V1 + 查询类型 + ABCD 策略 + 第 5 条 + 对比 | 未超越 V1 |

### 发现 5：prompt 工程的边际收益递减出现拐点

V3 是 V1 基础上叠加 ~500 字正面引导的新增内容，结果总分反降 0.7。不是说查询类型和 ABCD 策略无效——UX +0.13 和相关性 +0.11 是有价值的真实改善——而是在当前 8B 模型的注意力预算下，新增指令的正面效果被负面副作用覆盖了。Prompt 长度与模型注意力之间存在一个阈值，超过后增量信息被稀释。

---

## 决策

1. **V1-full 固化为 Prompt 工程最终方案。** 三个 Phase 都无法超越它。只改 ~180 字拿到整合 +0.26、总分 +0.4，ROI 最高。

2. **V3 中的有效成分值得在后续实验中独立测试。** 查询类型判断的 UX 收益（+0.13）和 ABCD 策略的相关性收益（+0.11）是真实信号。它们可能在其他条件下（更小改动量、单独叠加）不与准确性冲突。

3. **基于 Rubric 的极小改良在 V1 上尝试。** G-L5 格式化指令和 G-L1 精度指令合计不到 60 字，正面引导，不引入新结构，不增加注意力负担。如果能在不跌准确性的前提下把 UX 和准确性稍微推高，就是最终版。
