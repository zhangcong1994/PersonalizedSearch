## 已知局限（重要）

| # | 局限 | 实际影响 | 解决计划 |
|---|------|---------|---------|
| 1 | **无人机校准** | Judge（DeepSeek-chat）评分与人类标注的一致性未经验证。所有分数可能存在系统性偏差——Judge 可能整体偏严或偏松，或在某维度上与人类认知不一致 | 从 200 条中抽 50 条做双人标注 → 计算 Krippendorff's α / Spearman → 校准 Judge Prompt |
| 2 | **无双 Judge 交叉验证** | 仅用一种 Judge（DeepSeek-chat）评分，无法排除「用一个模型评估另一个模型」的内生偏差（in-group favoritism） | 用 GPT-4o-mini 做 Judge 交叉验证 20 条 → 对比评分分歧 |
| 3 | **模型覆盖不全** | 仅跑了 3 个 Qwen 系列小模型（1.5B / 4B thinking / 4B non-thinking）。缺少 7B 基线、GLM-4-9B 对照、Llama-3.1-8B 跨家族对照、DeepSeek-chat 上界、GPT-4o-mini 跨家族参照、理想排序输入测试 | 按 exp-005-generation.yaml 完整跑完 9 个模型 + ideal ranking |

## 实验设置（截至当前）

### 数据流

```
T2Ranking dev (1824 queries)
  → exp-004 bge-v2-m3 reranker top-10
  → 简单随机采样 200 条
  → 同一套 prompt（单版通用，含 2 个 few-shot）喂给各模型
```

## 阶段性发现（需后续验证确认）

### 发现 1：1.5B 模型在 AI 搜索的生成任务上不可用

Qwen2.5-1.5B 的平均分 22.5，94% 的答案被判定为不可用（D/F 级）。核心失败模式不是「知识不足」，而是**没有执行 AI 搜索的行为范式**：
- 引文质量：86% 的答案零引用（完全无视 prompt 中「标注来源」的要求）
- 整合质量：64% 的答案简单罗列，未做任何多文档融合
- 准确性：24% 的答案存在严重事实错误

> ⚠️ 注：1.5B 的 context window 达 32K，理论上能容纳全部输入。失败原因可能是 attention 在长上下文（~6000 tokens）中退化，或 prompt 遵循能力不足。需进一步分析具体 case 确认。

### 发现 2：Qwen3 的思考模式在 AI 搜索场景下轻微有害（非有益）

Qwen3-4B non-thinking 的五项生成维度全面优于 thinking 模式：

| 维度 | non-think | thinking | Δ |
|------|:---------:|:--------:|:---:|
| 准确性 | 3.08 | 2.90 | +0.18 |
| 相关性 | 3.66 | 3.48 | +0.18 |
| 用户体验 | 3.16 | 3.10 | +0.06 |
| 整合质量 | 2.26 | 2.28 | -0.02 |
| 引文质量 | 2.42 | 2.42 | 0.00 |
| **总分** | **59.0** | **57.4** | **+1.6** |

可能机制：思考模式生成的推理过程引入与检索文档不一致的先验知识，覆盖了文档中的正确答案，反而增加了幻觉。此外思考模式下模型倾向于「自己推导」而非「忠实引用」，与 AI 搜索的循证要求冲突。

**与官方结论的一致性分析**：

「Qwen3 思考模式普遍提升 benchmark 分数」的官方结论来自以下几类 benchmark：

| Benchmark 类型 | 思考模式效果 | 代表测试 | 任务特征 |
|---------------|:----------:|---------|---------|
| 数学推理 | ✅ 大幅提升 | AIME 2024: 73.8% (超过 R1-Distill-32B 的 72.6%) | 需要内部链式推理 |
| 知识问答 | ✅ 中幅提升 | MMLU-Redux: 83% → 86% | 依赖参数化知识 |
| 代码生成 | ✅ 中幅提升 | LiveCodeBench v5: 48.4 → 65.6 | 需要逐步规划 |
| 长上下文检索 | ❌ 下降 | RULER: thinking 模式有害 | 需要从外部文档提取信息 |
| **AI 搜索生成** | **❌ 下降** | **本实验: 59.0 → 57.4 (-1.6)** | **需要忠实复现外部文档** |

> **来源支撑**：
> 1. Qwen3 官方技术报告明确标注：「Thinking mode hurts retrieval-heavy tasks (e.g., RULER)」—— [Qwen3 Technical Report](https://arxiv.org/abs/2505.09388)
> 2. 阿里云百炼平台官方实践建议：非思考模式适用于「知识库检索、客服问答」场景，响应速度提升 60%，算力仅为思考模式的 1/3 —— [CSDN 阿里云官方技术文章](https://blog.csdn.net/weixin_72532546/article/details/160226282)
> 3. Qwen3 官方博客：思考模式适合「需要深度思考的复杂问题」，非思考模式适合「速度比深度更重要的简单问题」—— [Qwen3 官方博客](https://qwenlm.github.io/blog/qwen3/)
> 4. 第三方评测：Qwen3-4B thinking 在 AIME 2024 得分 73.8%，超过 R1-Distill-32B (72.6%)，但在检索依赖型任务上表现显著下降 —— [InsiderLLM](https://insiderllm.com/pdfs/best-local-llms-math-reasoning.pdf)
> 5. 论文 "Thinking Small Models are Efficient LLM Judges" 证明 thinking 在 LLM-as-a-Judge 任务上 +10pp 准确率，但该任务需要内部按 Rubric 推理，与 AI 搜索的「忠实于外部文档」需求相反 —— [arXiv:2509.13332](https://arxiv.org/abs/2509.13332)

**结论**：本实验发现并非反常，而是精确命中了 Qwen3 官方标注的局限范围。思考模式的收益高度依赖于任务是否以「内部推理」为核心——数学/代码/逻辑推理受益，知识库问答/AI 搜索/文档检索受损。在 AI 搜索的生成环节，**应默认禁用思考模式**。

```
                        思考模式有益 ←────────→ 思考模式有害
                              │                      │
          数学推理 AIME MATH-500  │    知识库问答 RULER
          代码生成 LiveCodeBench  │    AI 搜索生成 （本实验）
          Judge 评分 RewardBench  │    阿里云百炼 官方建议
                              │                      │
              任务需要          │         任务需要
           "内部链式推理"        │      "忠实于外部文档"
```

> ⚠️ 注：50 条样本量下差距未达显著。需 200 条全量数据后做配对 t 检验确认。

### 发现 3：「整合」和「引文」是所有模型的共同短板

即使表现最好的 Qwen3-4B-nonthink：
- 整合质量最高 3 分，**无一条得 4 分**
- 引文质量最高 3 分，**无一条得 4 分**

两个维度的天花板被卡在 3 分——能有效做事但做不到「优秀」。这可能反映了：
- (a) 搜索场景下多文档整合本质上是开放域的难度上限
- (b) 通用 LLM 的预训练目标（next-token prediction）与「精确引用外部文档」之间存在根本性的能力缺口
- (c) 当前 prompt 对引文格式的要求可能不够强，或格式要求与模型训练分布不匹配

> ⚠️ 注：需要和强 API 模型（DeepSeek-chat）的结果对比后，才能区分「是任务本身难」还是「小模型能力不足」。

## 关键技术决策记录

以下决策在实验设计和实现中做出，记录供后续备忘：

| 决策 | 选择 | 理由 |
|------|------|------|
| Judge 评估策略 | 两批 × 3 维（非一次 11 维、非一次 1 维） | 一次 11 维认知过载（后面维度被敷衍），一次 1 维缺少跨维度关联且调用量过大。每批 3 维平衡注意力和调用成本 |
| 生成 prompt | 单套通用（非 5 套分类型） | 分类器不准 + 分类型 prompt 引入混淆变量，同一套 prompt 确保模型对比是 apples-to-apples |
| 查询采样 | 简单随机 200 条（非分层） | 关键词分类器准确率仅 ~70%，分层引入噪声。保留分类标签仅用于后验分析 |
| 查询来源 | 从 reranker cache 提取（非 queries.dev.tsv） | ID 空间不匹配——dev.tsv 有 24831 条但 reranker 仅覆盖 1824 条 |
| 评估维度 | 先 6 维核心，后续扩展至 11 维 | 控制初版复杂度。5 个扩展维度（指令遵循、上下文利用、拒答判断、结构适配、内部一致性）的 prompt 已预置在代码中 |

- [ ] **人机校准**：从 200 条中抽 50 条，至少 2 人独立标注 6 维 → 计算 IRR（Krippendorff's α 或 Gwet's AC1）→ 若 α < 0.7，精炼 Rubric 定义 → 第二轮标注 → 用标注数据校准 Judge Prompt
- [ ] **双 Judge 交叉验证**：GPT-4o-mini 评 20 条 → 与 DeepSeek-chat 评分对比 → 若分歧大（Spearman ρ < 0.7），分析分歧维度 → 决定是否需要双 Judge 取均值或引入第三方 Judge
- [ ] **跑完全部模型**：200 条 × 9 个模型 = 1800 次生成 → 3600 次 Judge 调用 → ~¥35（DeepSeek API）

- [ ] **统计显著性检验**：200 条全量后做配对 t 检验 / Wilcoxon signed-rank → bootstrap CI（1000 次）
